# ۴. نقشه راه و فازبندی

## اصل فازبندی

هر فاز باید **به‌تنهایی قابل استفاده** باشد. فازی که فقط «نصف یک قابلیت»
تحویل می‌دهد، فاز نیست.

---

## فاز ۰ — پایه‌گذاری (۳ هفته)

**خروجی:** هیچ قابلیت کاربری، اما زیرساخت آماده.

| کار | خروجی |
|---|---|
| راه‌اندازی مخزن، CI/CD، محیط‌ها | dev / staging / prod |
| اسکلت Laravel + ساختار ماژولار | `app/Modules/*` |
| مهاجرت‌های پایه + Seeder | دیتابیس اولیه |
| موتور محاسبات + تست‌های آن | `Money`, `Weight`, `Purity` value objects |
| Audit Log و Idempotency middleware | زیرساخت عرضی |
| اسکلت Flutter + احراز هویت | لاگین ساده |
| توافق روی OpenAPI اولیه | قرارداد API |

**Definition of Done:** یک درخواست API با Idempotency-Key ثبت می‌شود،
در Audit Log می‌آید، و تست‌ها روی CI سبز هستند.

## فاز ۱ — MVP: عضویت + OTC + دفتر کل (۸ هفته)

**داستان محوری:**
> «دو طلافروش عضو شده‌اند، مستقیماً با هم معامله می‌کنند، سیستم تسویه را
> ثبت می‌کند و مانده هر دو درست است.»

### شامل

**M1 — هویت**
- ثبت‌نام، OTP، 2FA
- پروفایل حقیقی و حقوقی
- آپلود اسناد، حساب بانکی
- مدیریت کاربران و نقش‌ها

**M2 — KYC**
- صف بررسی، ماشین حالت، تاریخچه تصمیم

**M3 — طلا (پایه)**
- GoldLot ساده
- گواهی ری‌گیری (ثبت دستی)
- تفکیک عیار اعلامی از گواهی‌شده

**M5 — دفتر کل** ← **مهم‌ترین بخش فاز ۱**
- Gold Ledger + Rial Ledger
- Available / Reserved
- Rebuild و Reversal

**M6 — OTC + RFQ**
- پیشنهاد مستقیم بین دو عضو
- RFQ ساده

**M7 — تسویه (پایه)**
- ماشین حالت کامل
- Escrow
- T+0
- تأیید دوطرفه پرداخت

**M8 — قیمت (پایه)**
- ورود دستی/API قیمت مرجع

**M9 — موتور محاسبات** (کامل)

**M12 — ریسک (پایه)**
- سقف‌های ثابت

**M19/M20** — پنل ادمین حداقلی + Audit

### خارج از فاز ۱
Order Book، Matching Engine، خزانه، Split/Merge، تهاتر، AML، حسابداری کامل

## فاز ۲ — بازار: Order Book + Matching + خزانه (۱۰ هفته)

**داستان محوری:**
> «معامله‌گر بدون تماس تلفنی، قیمت را در دفتر سفارش می‌بیند و معامله می‌کند.
> طلا در خزانه است و مالکیت بدون جابه‌جایی منتقل می‌شود.»

### شامل

**M6 — بازار کامل**
- Order Book زنده
- Matching Engine (price-time priority)
- Limit / Market
- Partial Fill
- جلوگیری از Self-Trade
- جلسات معاملاتی
- WebSocket feed

**M4 — خزانه**
- تعریف خزانه و محل
- Vault IN / OUT با تأیید دوگانه
- تفکیک Owner از Custodian ← **قابلیت متمایزکننده**
- حواله و رسید

**M3 — طلا (پیشرفته)**
- Split / Merge / Melt
- شجره‌نامه
- QR Code

**M7 — تسویه (پیشرفته)**
- T+n
- تسویه جزئی
- مدیریت Overdue

**M10 — حسابداری**
- چارت حساب، ثبت دوطرفه، تراز

**M13 — AML (پایه)**
- Rule Engine، صف Flag

**M14 — اختلاف**

**M16 — اعلان کامل** (Push)

**M17 — گزارش‌ها**

**M18 — API عمومی**

**داستان محوری:**

**M7 — تهاتر**

**M15 — Reputation**

**M4 — خزانه چندگانه + انبارگردانی**

## مسیرهای موازی

این کارها در تمام فازها به‌صورت پیوسته ادامه دارند:

| مسیر | توضیح |
|---|---|
| **حقوقی و مجوز** | باید از روز اول شروع شود؛ نتیجه‌اش معماری را تغییر می‌دهد |
| **جذب عضو** | onboarding دستی و پرزحمت در فاز ۱ طبیعی است |
| **امنیت** | بازبینی کد، تست نفوذ در پایان هر فاز |
| **مستندسازی** | هر قابلیت بدون سند، تحویل‌شده محسوب نمی‌شود |

## ریسک‌های زمان‌بندی

| ریسک | احتمال | برنامه جایگزین |
|---|---|---|
| تأخیر مجوز | زیاد | فاز ۱ به‌عنوان «ابزار ثبت معامله و دفتر» عرضه شود (بدون Matching عمومی) |
| عدم امکان راه‌اندازی خزانه | متوسط | فاز ۲ بدون Custody، فقط Order Book |
| مقاومت بازار در برابر Order Book | متوسط | تمرکز بیشتر روی RFQ و OTC؛ Order Book به فاز ۳ منتقل شود |
| پیچیدگی تهاتر بیش از برآورد | متوسط | فقط تهاتر دوطرفه در فاز ۳؛ چندطرفه به فاز ۴ |
