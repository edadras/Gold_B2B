# ۹. حسابداری اختصاصی عضو

هر عضو عملاً یک ERP کوچک درون سامانه دارد. این ماژول از دفتر کل
(`Ledger`) تغذیه می‌کند و آن را به زبان حسابداری ترجمه می‌کند.

> **تفاوت مهم:** `Ledger` دارایی واقعی را ردیابی می‌کند.
> `Accounting` آن را در قالب دوطرفه برای گزارشگری مالی سازمان‌دهی می‌کند.
> این دو یکی نیستند و نباید ادغام شوند.

## ۹.۱ چارت حساب پیش‌فرض

</div>

```
۱ — دارایی‌ها (ASSETS)
  ۱۱ — دارایی‌های جاری
    ۱۱۰۱  صندوق
    ۱۱۰۲  بانک
    ۱۱۰۳  موجودی ریالی در سامانه
    ۱۱۱۰  موجودی طلا — در خزانه         (وزن + ارزش)
    ۱۱۱۱  موجودی طلا — نزد خود
    ۱۱۱۲  موجودی طلا — در ری‌گیری
    ۱۱۱۳  موجودی طلا — در راه
    ۱۱۲۰  حساب‌های دریافتنی — ریالی
    ۱۱۲۱  حساب‌های دریافتنی — طلایی
    ۱۱۳۰  پیش‌پرداخت‌ها
    ۱۱۹۰  دارایی‌های قفل‌شده (رزرو/تسویه)

۲ — بدهی‌ها (LIABILITIES)
    ۲۱۰۱  حساب‌های پرداختنی — ریالی
    ۲۱۰۲  حساب‌های پرداختنی — طلایی
    ۲۱۱۰  پیش‌دریافت‌ها
    ۲۱۲۰  کارمزد پرداختنی
    ۲۱۳۰  مالیات پرداختنی
    ۲۱۴۰  طلای امانی نزد ما (متعلق به دیگران)

۳ — حقوق مالکانه (EQUITY)
    ۳۱۰۱  سرمایه
    ۳۲۰۱  سود انباشته
    ۳۹۰۱  سود/زیان دوره جاری

۴ — درآمدها (REVENUE)
    ۴۱۰۱  فروش طلا
    ۴۲۰۱  سود تحقق‌یافته معاملات
    ۴۹۰۱  سایر درآمدها

۵ — هزینه‌ها (EXPENSES)
    ۵۱۰۱  بهای تمام‌شده طلای فروخته‌شده
    ۵۲۰۱  کارمزد سامانه
    ۵۲۰۲  کارمزد بانکی
    ۵۳۰۱  هزینه ری‌گیری
    ۵۳۰۲  هزینه حمل و بیمه
    ۵۳۰۳  هزینه نگهداری خزانه
    ۵۴۰۱  افت ذوب
    ۵۵۰۱  جریمه تأخیر
    ۵۹۰۱  سایر هزینه‌ها

۹ — حساب‌های انتظامی (MEMO)
    ۹۱۰۱  تعهدات معاملاتی باز
    ۹۲۰۱  طلای امانی
```

## ۹.۲ حساب‌های دوواحدی (طلا + ریال)

مشکل خاص این دامنه: برخی حساب‌ها **دو واحد سنجش** دارند.

</div>

```
حساب ۱۱۱۰ — موجودی طلا در خزانه

  کمیت اصلی   : 1,247.320 گرم خالص     ◄ واحد اصلی
  ارزش دفتری  : 96,043,640,000 ریال     ◄ واحد پولی (بهای تمام‌شده)
  ارزش روز    : 97,910,000,000 ریال     ◄ فقط اطلاعاتی
```

<div dir="rtl">

</div>

```sql
CREATE TABLE journal_entries (
  id                BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  organization_id   BIGINT UNSIGNED NOT NULL,
  voucher_no        VARCHAR(30) NOT NULL,
  entry_date        DATE NOT NULL,
  description       VARCHAR(500) NOT NULL,
  source_type       VARCHAR(50) NOT NULL,    -- trade, settlement, fee, ...
  source_id         BIGINT UNSIGNED NOT NULL,
  status            ENUM('DRAFT','POSTED','REVERSED') NOT NULL,
  posted_at         TIMESTAMP NULL,
  reverses_id       BIGINT UNSIGNED NULL,
  created_at        TIMESTAMP NOT NULL,
  UNIQUE KEY uq_org_voucher (organization_id, voucher_no),
  UNIQUE KEY uq_source (organization_id, source_type, source_id),  -- idempotency
  KEY idx_org_date (organization_id, entry_date)
) ENGINE=InnoDB;

CREATE TABLE journal_lines (
  id                BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  journal_entry_id  BIGINT UNSIGNED NOT NULL,
  account_code      VARCHAR(10) NOT NULL,
  counterparty_org_id BIGINT UNSIGNED NULL,   -- تفصیلی

  debit_rial        BIGINT UNSIGNED NOT NULL DEFAULT 0,
  credit_rial       BIGINT UNSIGNED NOT NULL DEFAULT 0,

  -- کمیت طلا برای حساب‌های طلایی
  debit_fine_mg     BIGINT UNSIGNED NOT NULL DEFAULT 0,
  credit_fine_mg    BIGINT UNSIGNED NOT NULL DEFAULT 0,

  description       VARCHAR(500) NULL,
  line_no           SMALLINT UNSIGNED NOT NULL,
  KEY idx_entry (journal_entry_id),
  KEY idx_account (account_code, journal_entry_id),
  KEY idx_counterparty (counterparty_org_id)
) ENGINE=InnoDB;
```

## ۹.۳ نگاشت رویداد به سند حسابداری

### خرید طلا

</div>

```
معامله: خرید 250 گرم خالص به مبلغ 19,521,900,000 + کارمزد 29,282,850

سند حسابداری خریدار:
┌────────────────────────────────────────────────────────────────┐
│ ردیف  حساب                        بدهکار         بستانکار      │
│                                   ریال / گرم     ریال / گرم    │
├────────────────────────────────────────────────────────────────┤
│  ۱   ۱۱۱۰ موجودی طلا در خزانه   19,521,900,000                 │
│                                     248.750 g                  │
│  ۲   ۵۲۰۱ کارمزد سامانه            29,282,850                  │
│  ۳   ۱۱۰۳ موجودی ریالی                        19,551,182,850   │
├────────────────────────────────────────────────────────────────┤
│      جمع                        19,551,182,850  19,551,182,850 │
│      جمع طلا                        248.750 g       248.750 g  │
└────────────────────────────────────────────────────────────────┘
                                                        ⚠️
```

<div dir="rtl">

> ⚠️ در ردیف ۳، حساب ریالی طلا ندارد. برای تراز شدن ستون طلا، ردیف ۱
> باید در برابر یک حساب انتظامی طلا قرار گیرد یا سیستم دو دفتر جداگانه
> نگه دارد.
>
> **تصمیم:** دو مجموعه ثبت مجزا:
> - ثبت ریالی: ردیف‌های ۱ (فقط مبلغ)، ۲ و ۳
> - ثبت طلایی: حساب `۱۱۱۰` بدهکار در برابر `۹۱۰۱ تعهدات` بستانکار
>
> این کار پیچیدگی را کاهش می‌دهد و هر ستون به‌صورت مستقل تراز می‌شود.

### فروش طلا

</div>

```
فروش 150 گرم خالص به مبلغ 12,000,000,000
بهای تمام‌شده (میانگین موزون): 11,550,000,000
کارمزد: 12,000,000

ثبت ریالی:
┌────────────────────────────────────────────────────────────────┐
│  ۱   ۱۱۰۳ موجودی ریالی          11,988,000,000                 │
│  ۲   ۵۲۰۱ کارمزد سامانه             12,000,000                 │
│  ۳   ۴۱۰۱ فروش طلا                            12,000,000,000   │
├────────────────────────────────────────────────────────────────┤
│  ۴   ۵۱۰۱ بهای تمام‌شده        11,550,000,000                  │
│  ۵   ۱۱۱۰ موجودی طلا (ارزش)                   11,550,000,000   │
├────────────────────────────────────────────────────────────────┤
│      جمع                        23,550,000,000  23,550,000,000 │

سود ناخالص = 12,000,000,000 − 11,550,000,000 = 450,000,000
```

## ۹.۷ نکات پیاده‌سازی

| نکته | جزئیات |
|---|---|
| **Idempotency** | `UNIQUE (organization_id, source_type, source_id)` روی `journal_entries` |
| **ثبت ناهمگام** | سند حسابداری در صف `accounting` تولید می‌شود، نه داخل تراکنش معامله |
| **بستن دوره** | پس از بستن، سند جدید در آن دوره ثبت نمی‌شود؛ اصلاح با سند اصلاحی در دوره جاری |
| **شماره سند** | ترتیبی به تفکیک سازمان و سال؛ بدون شکاف |
| **حذف** | ممنوع؛ فقط `REVERSED` |
| **دوره مالی** | قابل تنظیم به تفکیک عضو (اسفند یا دلخواه) |

</div>
